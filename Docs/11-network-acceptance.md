# 联网验收指南

本页给**自己做联网验收**的人：哪些已经被自动化测试真实验证过，哪些没有，以及怎么补验没覆盖的部分。

## 1. 已有的自动化联网测试

位置：`Source/RootMotionSourcePlus/Private/Tests/RMSNetTests.cpp`，只在带编辑器的构建里编译（`WITH_EDITOR`）。

运行：

```
UnrealEditor-Cmd <项目>.uproject -ExecCmds="Automation RunTests RMS.Net; Quit" -unattended -nullrhi -nosplash -NoSound
```

编辑器已经打开同一个项目时，命令行进程会被占用；此时请在编辑器里 **Tools → Test Automation** 里勾选 `RMS.Net` 运行。

这些测试用的是引擎自带的 `FTestWorlds`：同一进程里一个监听服务器加一个客户端，走真实的 NetDriver 与 CMC 的 ServerMove / ClientAdjust 流程，**不是模拟**。测试用的角色与 GameMode（`ARMSNetTestCharacter`、`ARMSNetTestGameMode`）是无重力、飞行模式的测试专用类。

| 测试 | 验证了什么 | 结果 |
| --- | --- | --- |
| `RMS.Net.Motion` | 服务器与客户端各自以相同参数 `PlayMotion`（直线 600 厘米 1 秒），终点两端一致，两端运动都正常结束 | 通过，终点差 0.00 |
| `RMS.Net.ReachMode` | 只在服务器放墙，观察两种到达模式下两端的分叉与收敛 | 通过，见下方解读 |
| `RMS.Net.Follow` | 跟随目标是会复制的 Actor，经真实 PackageMap 解析；运动中途服务器移动目标，客户端跟着走 | 通过，两端都落在目标上 |
| `RMS.Net.Curve` | 位移进度曲线（`CustomProgressCurve`）经真实 PackageMap 在两端一致；先证明曲线确实生效 | 通过，中途进度 0.765/0.776（线性应为 0.4） |
| `RMS.Net.Anim` | 动画资产经真实 PackageMap 被两端解析且不崩溃 | 通过，**但该动画不带根位移**，见 §3 |
| `RMS.Net.Path` | 折线、样条、抛物线：路径点逐点序列化；**中途**两端也一致（证明走的是同一条路径而不是殊途同归） | 通过：折线中途差 16.9、样条 17.3、抛物线 10.1；三种终点两端差均 0.0 |
| `RMS.Net.Force` | 恒力：两端各自施加，推进一致，两端各自 `StopAllMotions` 后停下，登记表清空；牵引：目标是会复制的 Actor，两端被拉到停止距离，目标移动后跟随 | 通过：恒力 2 秒服务器 796.8、客户端 803.4；牵引两端都停在距目标 144.3（停止距离 150），差 0.0 |

### 到达模式联网的真实结果（请重点读）

这是你最关心的风险。测试里只在**服务器**放一堵墙，客户端不知道有墙，所以客户端预测会一路走到目标，服务器被挡住：

| | 运动期间两端最大差 | 运动结束时两端差 | 观察 |
| --- | --- | --- | --- |
| `Guaranteed` | 554.7 | 0.0 | 客户端一路预测走到 800，服务器停在 245；运动结束后被拉回 |
| `Incremental` | 53.1 | 0.0 | 客户端在 245～298 之间**反复回弹**，肉眼可见的拉扯；运动结束后收敛 |

**必须理解的三点：**

1. 两种模式在运动结束时两端都收敛，但这是**引擎 CMC 的服务器位置校正**完成的，不是本插件保证的。
2. 运动**期间**两端必然分叉。客户端预测无法知道只有服务器才有的墙，这是预测的固有限制，不是缺陷。
3. `Incremental` 的拉扯在运动期间**肉眼可见**。如果你的玩法里“客户端会撞到服务器才有的东西”很常见，这是真实的体验代价，需要权衡。

## 2. 联网使用约定

- **两端各自调用 `PlayMotion`，参数必须逐位一致。** 起终点、路径点、时长如果来自各端各自的计算（比如各自读角色位置），可能有细微差异。能由一端确定的值，请由一端确定后再同步给另一端。
- 无限时长的力（`Duration < 0`）要两端都调用 `StopMotion` / `StopAllMotions` 才会在两端同时结束。
- 跟随目标、牵引目标必须是会复制的 Actor。

## 3. 没有被自动化验证的部分（需要你补验）

下列在代码里有实现、有单机的序列化与 `Matches` 测试，但**没有任何真实联网测试**：

| 项 | 为什么没测 | 你可以怎么补验 |
| --- | --- | --- |
| **动画根位移本身**的联网表现 | 引擎自带教程动画不带根位移（位移为 0），只验证了资产引用被解析 | 项目里有带根位移的攻击动画（如 `Content/Assets/Animation/G2/9CG_Dual/9CG_Dual_Attack_*`），在蓝图里两端各自 `PlayMotion` 并填入该动画 |
| **动画 Warping** 的联网表现 | 同上，且需要窗口标记 | 在动画上放 `RMS Warp Window` 标记，两端各自 `PlayMotion` |
| **偏移曲线**（`OffsetCurve`，`UCurveVector`） | 引擎自带内容里**没有**现成的 `UCurveVector` 资产，无法用真实资产测试；我不会用内存里临时造的曲线冒充（它没有稳定路径，本来就无法跨网络） | 在项目里创建一条 `UCurveVector` 资产，两端各自 `PlayMotion` 并填入 |
| **模拟代理**（第三方客户端看到的他人角色） | 只建了一个客户端 | 开两个客户端，让其中一个触发，观察另一个看到的平滑度 |
| **网络延迟与丢包** | 测试里是理想网络 | PIE 的 **Advanced Settings → Network Emulation** 开 100ms 延迟、2% 丢包 |
| **多客户端** | 只建了一个客户端 | PIE 里把客户端数量设为 2 以上 |
| **“对端解析不到资产时显式放弃”** | 真实网络下很难构造出解析失败 | 单元测试覆盖了读到空指针的处理；真实触发需要让客户端缺少该资产（例如仅服务器加载的内容） |
| **目标尚未复制到客户端时** 沿用已同步位置 | 需要精确控制复制时序 | 目标 Actor 刚生成的同一帧就 `PlayMotion` 跟随它，观察客户端是否中断 |

## 3.1 测试类在 Shipping 里的情况（请知悉）

联网测试用的 `ARMSNetTestCharacter`、`ARMSNetTestGameMode` 是反射类。UHT 不理会 `#if`，把它们包进 `#if WITH_EDITOR` 会让 UHT 生成的 `.gen.cpp` 引用未声明的类而导致 Shipping 编译失败（试过）。所以这两个类在 Shipping 里**作为 Transient 空壳存在**：只有构造函数里的几行设置，没有任何测试逻辑，体积可忽略。测试逻辑本身（`RMSNetTests.cpp`）由 `WITH_DEV_AUTOMATION_TESTS && WITH_EDITOR` 排除，Shipping 二进制里搜不到 `RMS.Net`。

如果上架 Fab 时在意这两个空壳类，需要另行处理（例如把测试代码拆成独立的 Editor 模块，但会增加 `.uplugin` 的复杂度）。
